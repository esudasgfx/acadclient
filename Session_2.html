3. Looping & Decision Making – for, if-else, while, do-while

3.1 The for Loop – Iterating Over Items

Python's for loop is designed to iterate directly over a sequence (like a list, tuple, string, or range). You don't need an index variable.

row = ['T3', '28-07-2026', 0, 6.0]

# 'val' takes the value of each element in order
for val in row:
    print(f"Current value: {val}")

# Output:
# Current value: T3
# Current value: 28-07-2026
# Current value: 0
# Current value: 6.0
  • Cleaner & safer: No manual index management – avoids "off‑by‑one" errors.
  • Works with any iterable: Strings, dictionaries, files, etc.

3.2 if-else Conditions – Making Decisions

Use if, elif (else if), and else to control the flow of your program based on conditions.

for val in row:
    if val == 1000:
        print("Found the sentinel value 1000!")
    elif val == 0:
        print("Zero duration detected.")
    else:
        print(f"Value is {val}")
  • if checks the first condition.
  • elif lets you check multiple conditions.
  • else runs if none of the above are true.

3.3 for vs while – When to Use Which

  • Use for when:
    • You know the number of iterations upfront (e.g., iterating over a list, range, or string).
    • You want to process each element in a collection without managing an index.
  • Use while when:
    • The number of iterations is unknown and depends on a dynamic condition (e.g., waiting for user input, reading a file until EOF, or running until a sensor value changes).
    • You need an infinite loop that breaks on a specific event.
Rule of thumb: In Python, for is preferred 80% of the time because it's more readable and less error‑prone. Only use while when you truly need an indefinite loop.

3.4 do-while / do-until – Does Python Have Them?

No. Python does not have a built‑in do-while or do-until loop. This is a deliberate design choice – Python's philosophy prioritizes readability and explicit flow control.

However, you can simulate a do-while (execute at least once) using:

# Simulate do-while: run code at least once, then check condition
while True:
    # This block always runs at least once
    user_input = input("Enter a number (or 'exit'): ")
    if user_input == 'exit':
        break # exit the loop
    print(f"You entered: {user_input}")
  • do-while pattern: Use while True and place the exit condition at the end with break.
  • do-until pattern: This is the same as do-while but with a negation. Just use if condition: break when you want to stop.
Remember: In languages like C or Java, do-while checks the condition after the loop body. Python's while checks it before. So always use the while True + break pattern when you need an "at‑least‑once" loop.

4. Beyond Python – Frontend + Backend Integration

The session also touched upon an HTML page with JavaScript that sends data to a server. This is a typical client‑server architecture. Let's break it down.

4.1 The HTML Frontend

<table>
    <tr>
        <td><p> Enter Task Name </p></td>
        <td><input type="input" id="taskname" /></td>

    </tr>

  • This creates a simple form with a text input and a submit button.
  • When clicked, sendToServer() JavaScript function is called.

4.2 The JavaScript Client

function sendToServer() {
    // 1. Build HTTP Request (GET, POST, etc.)
    // 2. Set headers (authentication, content-type)
    // 3. Send to a backend URL (Web API / Web Service)
    // 4. Handle the response (parse JSON, update UI)
    saveToDB(); // or save to file, send email, etc.
}
  • This function would typically use fetch() or XMLHttpRequest to communicate with a backend.
  • Common actions: save to a database, write to a file, send an email, or upload to SharePoint.

4.3 The Backend (Python / Node / etc.)

The backend receives the request, processes the data, and performs actions like:

  • Save to a text file – using Python's open() and write().
  • Insert into a database – like Oracle, SQL Server, or PostgreSQL.
  • Send an email – using smtplib.
  • Upload to SharePoint – via Microsoft Graph API or SharePoint REST API.
Takeaway: The frontend captures user input; the backend processes and stores it. This is the foundation of most web applications.

5. Key Takeaways from Today's Session

  • Variables store data – no type declaration needed.
  • Lists hold ordered collections – accessed by index or iterated with for.
  • while loops are great when you don't know how many times to loop.
  • for loops are cleaner and safer when iterating over known collections.
  • if-elif-else lets you branch your code based on conditions.
  • Python doesn't have do-while – use while True + break to simulate it.
  • input() reads user input as a string; convert to int or float for arithmetic.
  • Type conversion is essential when mixing data types.
  • Frontend + Backend work together to create complete applications.
